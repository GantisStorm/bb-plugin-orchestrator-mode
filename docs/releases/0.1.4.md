# Orchestrator Mode 0.1.4

This patch pins workers to the scope's stored execution, adds explicit subagent policies, removes the 30-second startup stall, and queues direct child messages while a turn is running.

## Worker model policy

- **Per-unit model overrides** in the scope editor, and `scope --model-policy pinned|flexible` on the CLI.
- `Pinned` refuses a delegation's `model`, `provider` and `reasoning`, and says so in the contract. Stored presets still apply.
- `Flexible` keeps the previous behaviour: a delegation may pass those three, and the contract still advises a stronger model for a hard unit.
- The default is `Pinned`. A scope that never opened the setting runs every worker on the stored execution or a stored preset.

## Subagent policies

- **Orchestrator subagents** default to `read-only`, with `all` and `none`. Set them with `scope --orchestrator-subagents`.
- **Worker subagents** default to `blocked`, with `allowed`. Set them with `scope --worker-subagents`.
- The watchdog judges identified provider subagents instead of always allowing them. The read-only default needs launch-specific provenance, which BB does not yet expose, so native reading support stays blocked on that metadata. Familiar names and cached telemetry grant no trust.
- Codex coordination stays allowed. Unrelated task arrays keep their normal classification. Legacy opaque OMP calls remain unverified work.
- Every policy is explicit in the contract and grants no extra user or parent authority.
- A blocked worker receives an injected rule against starting subagents. BB cannot remove the provider's own tool, so the rule is an instruction rather than enforcement.
- A correction sent to a thread this orchestrator owns, including a hidden child and a fork, counts as coordination rather than direct work.

## Startup and queued child messages

- Discover worker models and recover queues after registration, so plugin startup no longer waits on itself for 30 seconds. Saved worker choices stay in place until discovery succeeds. Failed reads retry, and consumers cancel on reload.
- Direct child messages wait in BB's persistent queue while an orchestrator turn is running, and deliver when the turn is idle. Global and project settings, and `scope --child-messages queued|immediate`, control this. Automatic child system notices still use BB's separate path.
- Compatible queued updates from the same child deliver together. Each child's order is kept, including interleaved arrivals. Pending batches recover on reload.
- The per-turn delegation budget survives messages that join a running turn or wait in the queue. It resets only when a new turn starts.

## Upgrade notes

- Worker model policy defaults to `Pinned`. Switch a scope to `Flexible` to let a delegation change model, provider or reasoning again.
- Orchestrator subagents default to `read-only` and worker subagents default to `blocked`. A native reading agent is not exempt until BB exposes launch-specific read-only provenance.
- Direct child messages default to `queued`. Set child messages to `immediate` to deliver them during a running turn.
- No dependency or SDK upgrade is included.
